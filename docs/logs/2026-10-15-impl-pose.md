## 1. Problem Analysis

### P0-04: Silent loss of terminal outcomes in `PoseManager`
- `submit_request()` rejects requests (due to queue overflow, lower-priority shedding, or older core epoch) and stores the resulting `PoseOutcome` in `self._terminal_outcomes`.
- `set_epoch()` cancels older epoch requests and appends them to `self._terminal_outcomes`.
- However, `process_pending()` only returns outcomes from `self.scheduler.schedule_batch(current_time)` and previously completely ignored `self._terminal_outcomes`.
- Furthermore, `process_pending()` previously executed `self._terminal_outcomes.extend(outcomes)` at line 880, which would cause previously returned outcomes to be re-added to `_terminal_outcomes`, resulting in duplicate returns if drained repeatedly.
- In `request_pose()`, outcomes were also appended to `self._terminal_outcomes`, which caused synchronous requests to have duplicate asynchronous returns in subsequent `process_pending()` calls.
- `pipeline.py` calls `process_pending(current_time=ts)` and never calls `poll_terminal_outcomes()`, causing rejected and cancelled outcomes to be lost silently.
- **Contract Violation (`contracts.md §1`):** "Consumer chậm không làm mất terminal outcome im lặng... Request được nhận có đúng một terminal outcome trong epoch đang sống".

### P2-08: Clock domain inconsistency in `PoseOutcome.executed_at`
- `schedule_batch()` previously set `executed_at=current_time` (event-time).
- `process_pending()` set `executed_at=time.time()` (wall-clock time) for all processed outcomes.
- Result: outcomes returned in the same batch mixed event-time (e.g., 5.0) with wall-clock time (e.g., 1776234567.89).
- `request_pose()` also set `executed_at=time.time()` even when `current_time` was passed and `clock_domain="event_time"`.
- **Solution:** Standardize `executed_at` according to `req.clock_domain`. For `event_time`, use `current_time` (or `req.created_at`). For other domains (such as wall-clock), use `time.time()`.

### Stage 2: Green Phase
Modified `apps/edge/pose.py`:
1. Added `_resolve_executed_at(req: PoseRequest, current_time: float | None = None) -> float`:
   - If `req.clock_domain == "event_time"`: returns `current_time` if provided; otherwise `req.created_at` or `req.deadline`.
   - If other clock domain: returns `time.time()`.
2. Updated `PoseScheduler.schedule_tracks`: set `created_at=current_time` explicitly when constructing `PoseRequest`.
3. Standardized `executed_at` across `PoseScheduler.submit_request`, `_try_shed_lower_priority`, `schedule_batch`, and `set_epoch`.
4. In `PoseManager.submit_request`:
   - Resolved `executed_at` via `_resolve_executed_at`.
   - Polled shed outcomes from scheduler on every submit, extending `self._terminal_outcomes`.
5. In `PoseManager.process_pending`:
   - Under `self._lock`: extracted `terminal_outcomes = list(self._terminal_outcomes)` and cleared `self._terminal_outcomes.clear()`.
   - Combined `outcomes = terminal_outcomes + list(shed_outcomes)`.
   - Processed each scheduled request using `_resolve_executed_at(req, current_time)`.
   - Removed `self._terminal_outcomes.extend(outcomes)` at the end of `process_pending` to prevent duplicate returns on subsequent calls.
6. In `PoseManager.request_pose`:
   - Standardized `executed_at=_resolve_executed_at(req, eval_time)`.
   - Removed `self._terminal_outcomes.append(outcome)` from synchronous evaluation paths to avoid polluting `_terminal_outcomes`.
