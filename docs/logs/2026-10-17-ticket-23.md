# Ticket #23 — Track gap không tạo certainty hoặc motion giả (2026-10-17)

## Khoảng trống tìm thấy (test đỏ trước)
- `Track.update` không kiểm tra khoảng cách thời gian: track lost được re-associate sau gap vẫn giữ history → `vertical_velocity` tính qua gap (motion giả); tentative hits cộng dồn qua gap.
- Clock nhảy lùi không reset history.
- `IncidentEngine.process_tracks` chỉ reset state khi track vắng mặt hoặc có `observation_gap()` tường minh; frame cách xa/clock nhảy vẫn giữ `first_qualifying_time`/onset → lying/fall dwell giả (ví dụ lying t=1.0 rồi t=10.0 phát event anchor 0.0).

## Thay đổi
- `Track.max_gap` (mặc định 1.0s; `ByteTracker(max_observation_gap=1.0)`): nếu `ts < last_time` hoặc gap > max_gap thì xóa history và `consecutive_hits=0` trước khi ghi observation mới. ID và state giữ nguyên (không nối bằng bbox proximity mới).
- `IncidentEngine(max_observation_gap=1.0)`: gap/clock nhảy trên một track → state mới, chỉ giữ `last_alert_time`/`triggered` (cooldown). Dwell, onset, standing evidence, speed baseline bị reset.
- Missing (track vắng frame) vẫn reset state như cũ, không coi là negative.
