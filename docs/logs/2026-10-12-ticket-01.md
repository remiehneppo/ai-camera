# Ticket #01 — Synthetic event vertical slice — 2026-10-12

## Decisions

- Started the first ready frontier ticket, #01, from `.scratch/system-build-slices/PRD.md`; the repository initially contained docs and tickets only.
- Followed accepted ADRs: Python/FastAPI + MongoDB, one-member replica set for lab, SQLite event/outbox at edge, dashboard-only downstream policy.
- Pinned the local lab to MongoDB 7.0.43 after MongoDB 8.0.32 refused to start on the host's Linux 6.19 kernel. The failed 8.0 attempt volume was left untouched; 7.0 uses a distinct named volume.
- Pinned the event canonicalization to `canonical-json-python-v1` (normalized UTC timestamps, UTF-8 JSON, sorted keys, compact separators, finite numbers), with a fixed hash vector. Event identity and origin are immutable across revisions.
- The Compose API binds only to loopback. The edge client requires HTTPS except when `ALLOW_INSECURE_LAB=1` and the target is loopback.
- CodeGraph reported zero indexed files before and after implementation; no structural index results were available.

## Implementation and evidence

- Added a shared full-snapshot contract, bounded validation and canonical hash; edge SQLite event/outbox transaction; HTTPS-first retry client with receipt verification; FastAPI device-authenticated ingestion; Mongo transaction for immutable revision/current projection/ineligible downstream intent; and API-backed demo dashboard.
- Added Compose with persistent MongoDB volume, replica-set init/readiness, dependencies, and run instructions.
- `python3 -m unittest discover -s tests -v`: 10 passed, including invalid schema, revision identity, canonical hash, SQLite rollback, retry identity and receipt mismatch.
- `python3 -m py_compile domain/event_contract.py apps/edge/outbox.py apps/edge/send_synthetic.py apps/server/store.py apps/server/main.py tests/test_event_delivery.py`: passed.
- `docker compose config` with placeholder lab tokens: passed.
- `docker compose up --build -d` with placeholder lab tokens: MongoDB 7.0.43 and server started; Mongo transaction readiness probe completed.
- HTTP smoke checks: `/healthz` 200; `/` 200; edge synthetic POST committed and returned a receipt; dashboard events returned 200; bad dashboard token 401; authenticated device mismatch 403; oversized body 413; same revision retry returned the same receipt; same-key changed content 409; origin substitution 409; revision 3 followed by 1 kept current at 3.
- MongoDB state after smoke checks: 4 revisions, 3 current projections, 4 synthetic/replay ineligible downstream decisions, 0 eligible intents.

## Limits

- Browser-rendered UI, hardware, field, crash/power-cut, long-soak and production TLS/reverse-proxy acceptance remain unverified.
- The synthetic fixture requests no evidence, so pin/capture behavior was not exercised; that remains ticket #07.
- The failed MongoDB 8.0 trial left an unused version-specific Docker volume; it was not deleted. The working MongoDB 7.0.43 volume contains only synthetic smoke-test records.
