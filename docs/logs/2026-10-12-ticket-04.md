# Ticket #04 — Review event có kiểm soát phiên bản

Ngày: 2026-10-12. Ticket: [#04](../../.scratch/system-build-slices/issues/04-review-event-co-kiem-soat-phien-ban.md).

## Hành động

- Added optional `REVIEWER_TOKENS` as reviewer ID → bearer token. Existing dashboard auth remains read-only for review writes; secrets are excluded from the config hash, IDs are included, and reviewer tokens may not reuse dashboard/device credentials.
- Added bounded, strict review request validation and legal transitions: unreviewed → confirmed/false_positive; confirmed → resolved; any reviewed state → explicit reopen. Every mutation requires a reason and records actor, review version, viewed event revision/hash, and evidence versions.
- Persisted review state and append-only audit separately from AI snapshots. Mongo transaction updates a current-event guard to serialize reviews against newer AI revisions; optimistic review versions make concurrent stale actions return 409.
- A changed taxonomy, severity, or evidence version marks `needs_re_review` while preserving the previous decision. A review against an older revision is accepted only when review-meaningful content is unchanged.
- Added dashboard review controls, audit display, and refresh-on-conflict with no automatic resubmit.
- Compatibility decision: ONNX CPU/x86 + file replay is the current baseline. RKNN will use a distinct target artifact behind the same `PerceptionPipeline` semantics; RTSP changes source configuration, not event schema. RKNN and RTSP have not been runtime-tested.
